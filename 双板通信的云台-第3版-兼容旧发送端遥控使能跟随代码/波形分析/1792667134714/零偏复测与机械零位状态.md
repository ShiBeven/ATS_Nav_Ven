当前GetgimbalMode在valid0时保持ZERO_FORCE。这直接解释当前为何不进入初始化；没有超速/通信错误锁存的截图证据。

按照实际旧换算函数ECD_RANGE=8191和PITCH_TURN=1：

```
ecd差 = 5822 - 0 - 8191 = -2369
Pitch相对角 = -(-2369) × 0.000766990394 ≈ 1.817rad
```

与CSV约104.1度一致，但板载INS俯仰约2.56度。当前相对角是缺少正确机械偏移后的数值，不能直接作为投影角重新使能。cos(1.817)约-0.244、sin约0.970；当前小Yaw速度公式采用这一角，动态投影参考需要在有效校准加载后重新核对。

陀螺仪校准处理INS_gyro的偏置，机械限位校准处理电机编码器零位与行程，两套数据独立。GYR流程本身不会计算Pitch.offset_ecd。

## 恢复顺序

1. 不需要修改PID或再次烧录。当前valid0/status0，确认Pitch连杆、真实机械限位及小Yaw真实限位可靠，双拨杆下位，准备随时断动力。机械校准会主动驱动Pitch和小Yaw，大Yaw发送命令应为0。
2. 使用现有两段云台校准遥控手势；或在当前status0的前提下，Watch将`cali_sensor[1].cali_cmd`从0写1。枚举1是云台机械校准，枚举2是陀螺仪。
3. 观察step1→2（Pitch）、3→4（小Yaw），完成后应status2/valid1/error0/step0。若status3，保留error/error_step，按故障处理；不要通过直接写valid1来跳过参数校验。
4. 保持双下，等待保存结束，断开电机动力后让控制板重新上电。有效重载应status4/valid1，offset及限位与刚完成时一致。
5. 如果重启又valid0/status0，再检查Flash记录保存、G2P格式标记及下载擦除范围。当前参数区是Sector9；只有实际擦除该区才会因下载丢参数，不能只凭CSV断定已经发生了全片擦除。
6. 先确认机械角参考、静止速度和参数重载，再进行分阶段低幅正常控制验证。当前报告不宣称持续抖动已经解决。
