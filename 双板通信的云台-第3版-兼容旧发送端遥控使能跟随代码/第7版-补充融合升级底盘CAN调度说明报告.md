# 第7版：补充融合升级底盘 CAN2 调度

## 1. 问题

第6版能够编译，云台任务和导航/自瞄接收链路已经存在，但 `HAL_TIM_PeriodElapsedCallback()` 只发送云台电机电流和视觉状态，没有把遥控器数据转发到 CAN2。底盘因此收不到 0x111、0x112、0x120 控制帧。

## 2. 对比结论

可工作的 `D:\虚拟c盘\融合升级\融合升级` 工程在 TIM2 中使用 20 ms 分时调度：

| CAN 标识符 | 内容 | 第7版处理 |
|---|---|---|
| 0x111 | 遥控器通道和开关 | 已补 `CAN_SendRcBasic` |
| 0x112 | 辅助通道、键盘 | 已补 `CAN_SendRcAux` |
| 0x120 | 鼠标 | 已补 `CAN_SendRcMouse` |
| 0x113 | 导航 vx/vy/wz | 保留并纳入同一 CAN2 调度 |
| 0x121 | 云台 yaw 编码器状态 | 保留原 TIM6 发送 |

## 3. 修改内容

- 从第6版完整复制建立本版本，第6版源代码未覆盖。
- 在 `application/CAN_receive.c` 增加三类遥控器 CAN2 打包函数，使用大端有符号 16 位格式，与对比工程一致。
- 在 `Src/bsp_pid.c` 的 TIM2 中增加 `can2_slot`，每 1 ms 递增，20 ms 循环，在 slot 0/2/4/8 分别发送遥控器基础帧、辅助帧、鼠标帧和导航速度帧。
- 导航帧 bytes 6、7 明确清零，避免复用旧数据。
- 原有云台电流、导航/自瞄接收、FreeRTOS 任务和视觉状态发送路径未删除。

## 5. 烧录后验证顺序

1. 用 CAN 分析仪接 CAN2，确认遥控器有效时周期出现 `0x111`、`0x112`、`0x120`。
2. 上位机发送导航或融合帧后确认 `0x113`，数据为大端 `int16(vx*100)`、`int16(vy*100)`、`int16(wz*100)`。
3. 确认云台 yaw 状态帧 `0x121` 正常发送。
4. 若上述帧均存在而底盘不动，检查底盘 CAN 接收过滤器、CAN 波特率、急停/使能和底盘端超时保护；若没有帧，再检查 TIM2 中断、CAN2 启动和遥控器 DBUS 接收。

本报告只证明代码已完成编译和链接，不能替代实车 CAN 抓包及底盘动作验证。
