# 第3版：兼容旧发送端，通过遥控授权持续跟随

本版基于第2版修改，适配当前54字节命令中 tracking 持续为0的发送端。左中右下且通信正常时，fire=0也可以跟随；不再依靠fire脉冲维持导航接管。已编译，未下载到板子或实机验证。

## 发送端查找结论

原工程Src/usbd_cdc_if.c中的CDC_Receive_FS把外部USB数据交给unified_usb_receive_bytes，application/usb_task.c是解析接收端。D:/code-ai/导航-第2版等STM32导航工程的GetCmdData也是读取RECEIVE_ROBOT_CMD_DATA，并不是产生视觉目标的ROS发送节点。

原工程“验证/视觉接口协议对齐/导航与视觉和电控通信接口文档.md”记录的发送工程为Linux路径：

```text
/home/ats/ATS
src/standard_robot_pp_ros2/src/standard_robot_pp_ros2.cpp
src/standard_robot_pp_ros2/include/standard_robot_pp_ros2/packet_typedef.hpp
```

文档描述sp_vision25通过/serial/gimbal_cmd把视觉命令交给standard_robot_pp_ros2，再由其打开USB串口。以上是工程内文档提供的线索，不是本次登录Linux设备确认的路径。本机已搜索的D:/code-ai、D:/虚拟c盘及相关工程目录中没有找到该ROS节点源码；本机WSL未安装。搜索曾遇到不相关PPT目录访问拒绝。未修改其他“导航”工程来冒充修复真实发送端。

## 兼容机制

正常携带tracking的54字节命令沿用第2版路径。tracking为0时，新增本地兼容接管，需要同时满足：

1. application/usb_task.h中的USB_ATS_LEGACY_RC_AIM_COMPAT=1（本版默认开启）。
2. 遥控CAN数据未超时，左拨杆中、右拨杆下。
3. 最近有效54字节导航命令距离当前不超过100ms。
4. 该54字节发送时间戳在最近100ms内有变化。首帧建立时间基准；不断重发同一时间戳不能无限保活。
5. 最新命令的pitch/yaw是有限数值，拒绝NaN和正负无穷的兼容接管。这里不是机械角度限幅，原有角度控制/限位逻辑仍需正常工作。

兼容接管下：fire=0→Vision_state=1；fire非零→Vision_state=2。两者都允许AUTO_AIM，控制执行仍经过原有初始化、标定、遥控和IMU保护。Move/Attack策略和fric_on不作为兼容使能。

新增全局只读观测量usb_nav_compat_active：1表示正在使用本地遥控兼容授权；0表示未使用该兼容路径，不代表所有视觉源都无效。接收到的tracking原值保持不变，方便继续诊断。

拨杆离开左中右下、遥控超时、USB接收超时或发送时间戳停滞超过100ms，会撤销兼容接管；拨杆和遥控错误在USB任务循环中复查，不依赖下一帧到来。撤销后按原规则回退到新鲜独立视觉命令，没有有效替代命令则mode=0。50/52字节协议切换会清理兼容标志，避免旧标志错误覆盖其原有处理。

## 必须理解的限制

本版接受的是“操作者授权的导航角度命令”，并没有补出真实的视觉目标有效信号。如果上位机丢失目标后仍不断发送带新时间戳的旧角度，本板无法区分它和“目标静止”，会继续按接收到的角度保持。此时用遥控退出；不要把兼容标志当作目标检测状态。

今后发送端正确提供tracking后，应将USB_ATS_LEGACY_RC_AIM_COMPAT设0并重新编译，恢复第2版严格语义。兼容开关为1时，tracking从1变0也可能转入遥控兼容，因此不能把该开关保持开启用于要求tracking0立即退出的升级发送端。

本版保留fire对发射授权的原有意义，连续跟随不会额外强制fire=1。其他输入路径和发射机构的既有控制规则未修改。

## 使用顺序

1. 打开本目录MDK-ARM/PROJECT.uvprojx，确认目录含“第3版-兼容旧发送端遥控使能跟随代码”。
2. 使用本版本MDK-ARM/OBJ/PROJECT.hex下载；调试和J-Scope使用同一次构建的PROJECT.axf。不要继续使用原目录或第2版AXF的旧符号地址。
3. 按已有正常操作完成初始化、标定及必要的故障复位；先左下右中，让绝对角度模式稳定，再切到左中右下。第3版未修改右拨杆下时的INIT退出规则；若初始化本身失败，应排查而非绕过。
4. 先无弹验证固定可见目标、不开火：预期tracking仍可为0，usb_nav_compat_active=1，Vision_state=1，gimbal_behaviour稳定8。
5. fire在0/1切换时，Vision_state应在1/2切换，gimbal_behaviour不应仅因fire归零而退出。随后验证遥控退出、通信断流与故障保护。
6. 建议记录usb_nav_compat_active、Vision_state、gimbal_behaviour、pitch_can_send、pitch_can_set_current、实时motor_gyro。模式稳定后再判断PID跟随；本版没有修改PID参数，也不能保证已有大电流脉冲或其他控制问题全部消失。
