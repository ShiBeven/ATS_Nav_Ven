# 导航、视觉与电控通信接口文档

本文档描述当前 ATS 工程中，导航和视觉如何通过 ROS 2 与 `standard_robot_pp_ros2` 串口节点通信，再由串口节点把协议帧发送给电控。

适用代码目录：

```text
/home/ats/ATS
```

串口的唯一属主是 `standard_robot_pp_ros2`。导航和视觉程序不应再直接打开同一条电控 USB 串口。

## 1. 总体数据流

### 1.1 底盘导航链路

```text
Nav2 controller_server
  -> cmd_vel_controller
  -> trajectory_speed_governor
  -> cmd_vel_controller_governed
  -> velocity_smoother
  -> cmd_vel_nav2_result
  -> fake_vel_transform
  -> cmd_vel_gimbal_yaw_odom
  -> sentry_chassis_vel_transform
  -> /cmd_vel
  -> standard_robot_pp_ros2
  -> USB 串口
  -> 电控底盘
```

`standard_robot_pp_ros2` 只订阅绝对话题 `/cmd_vel`。如果只启动 Nav2 而没有启动 `sentry_chassis_vel_transform`，`/cmd_vel` 不会有发布者。

### 1.2 视觉云台链路

```text
电控
  -> USB 串口
  -> standard_robot_pp_ros2
  -> /serial/gimbal_state
  -> sp_vision25 GimbalTopicBridge
  -> /serial/gimbal_cmd
  -> standard_robot_pp_ros2
  -> USB 串口
  -> 电控云台
```

导航串口节点负责打开串口、解析电控状态、转发视觉云台指令。`sp_vision25` 使用 ROS 2 话题，不应和导航节点同时打开电控串口。

## 2. ROS 2 话题接口

| 方向 | 话题 | 消息类型 | 作用 |
|---|---|---|---|
| 导航 -> 串口节点 | `/cmd_vel` | `geometry_msgs/msg/Twist` | 底盘速度 |
| 行为树 -> 串口节点 | `decision/robot_mode` | `example_interfaces/msg/UInt8` | 姿态模式 |
| 串口节点 -> TF | `serial/gimbal_joint_state` | `sensor_msgs/msg/JointState` | 云台/底盘大 yaw 关节反馈 |
| 串口节点 -> 视觉 | `serial/gimbal_state` | `std_msgs/msg/Float64MultiArray` | 云台状态，共 11 个元素 |
| 视觉 -> 串口节点 | `serial/gimbal_cmd` | `std_msgs/msg/Float64MultiArray` | 云台控制，共 7 个元素 |
| 串口节点 -> 导航 | `serial/robot_motion` | `geometry_msgs/msg/Twist` | 电控反馈的实际运动速度 |
| 串口节点 -> 系统 | `serial/imu` | `sensor_msgs/msg/Imu` | IMU 状态 |

当前根命名空间应保持为空。`/cmd_vel` 是绝对话题，视觉云台相关话题使用相对名称但当前部署也按根命名空间运行。

### 2.1 `/cmd_vel` 底盘速度

字段对应关系：

```text
Twist.linear.x   -> SendRobotCmdData.data.speed_vector.vx
Twist.linear.y   -> SendRobotCmdData.data.speed_vector.vy
Twist.angular.z  -> SendRobotCmdData.data.speed_vector.wz
```

`linear.z`、`angular.x`、`angular.y` 不参与底盘协议发送。

串口节点还具有以下保护：

- 短时零速保持，减少上游偶发零帧造成的停走抖动；
- `cmd_vel` watchdog，超过 `cmd_vel_watchdog_timeout_ms` 没有新速度时主动清零；
- 串口未连接时不发送，并持续尝试重连。

### 2.2 `decision/robot_mode` 姿态模式

模式值必须和电控协议一致：

| 模式 | 数值 |
|---|---:|
| attack | 1 |
| defend | 2 |
| move | 3 |

非法值会回退为 `move(3)`。该值写入底盘发送帧的 `speed_vector.mode` 字段。

### 2.3 `serial/gimbal_state` 云台状态

消息类型是 `std_msgs/msg/Float64MultiArray`，数组必须有 11 个元素：

```text
[0] mode
[1] q_w
[2] q_x
[3] q_y
[4] q_z
[5] yaw
[6] yaw_vel
[7] pitch
[8] pitch_vel
[9] bullet_speed
[10] bullet_count
```

角度和角速度使用弧度、弧度每秒。视觉侧 `GimbalTopicBridge` 订阅该话题，供自瞄计算使用。

### 2.4 `serial/gimbal_cmd` 视觉云台指令

消息类型是 `std_msgs/msg/Float64MultiArray`，数组必须有 7 个元素：

```text
[0] mode
[1] yaw
[2] yaw_vel
[3] yaw_acc
[4] pitch
[5] pitch_vel
[6] pitch_acc
```

云台模式：

```text
0 = stop
1 = aim
2 = aim and fire
```

所有角度、角速度、角加速度使用弧度制。串口节点会拒绝长度不为 7、包含 NaN/Inf 或模式不在 0 到 2 范围内的消息。

视觉侧实现位置：

```text
src/sp_vision25/io/ros2/gimbal_topic_bridge.hpp
src/sp_vision25/io/ros2/gimbal_topic_bridge.cpp
src/sp_vision25/src/auto_aim_debug_mpc.cpp
```

## 3. 串口协议帧

协议基础定义位于：

```text
src/standard_robot_pp_ros2/include/standard_robot_pp_ros2/packet_typedef.hpp
src/standard_robot_pp_ros2/include/standard_robot_pp_ros2/packet_typedef_addon.hpp
```

每个协议帧使用以下结构：

```text
HeaderFrame + time_stamp + data + CRC16
```

帧头为：

| 字段 | 大小 | 说明 |
|---|---:|---|
| `sof` | 1 byte | 固定 `0x5A` |
| `len` | 1 byte | 从时间戳到数据段末尾的长度，不含帧头和 CRC16 |
| `id` | 1 byte | 数据包 ID |
| `crc` | 1 byte | 帧头 CRC8 |

完整帧最后附加 CRC16。浮点数按 C++ `float` 写入，结构体使用 packed 布局；电控端必须使用相同的字段顺序、大小端和 CRC 算法。

### 3.1 底盘控制帧

```text
方向：视觉/导航计算机 -> 电控
ID：ID_ROBOT_CMD = 0x01
结构：SendRobotCmdData
```

关键数据：

```text
speed_vector.vx
speed_vector.vy
speed_vector.wz
speed_vector.stop
speed_vector.mode
```

代码位置：

```text
src/standard_robot_pp_ros2/src/standard_robot_pp_ros2.cpp:924
src/standard_robot_pp_ros2/include/standard_robot_pp_ros2/packet_typedef.hpp:375
```

### 3.2 云台控制帧

```text
方向：视觉计算机 -> 电控
ID：ID_GIMBAL_CMD = 0x02
结构：SendGimbalCmdData
总大小：35 bytes
```

代码位置：

```text
src/standard_robot_pp_ros2/src/standard_robot_pp_ros2.cpp:1002
src/standard_robot_pp_ros2/include/standard_robot_pp_ros2/packet_typedef_addon.hpp:40
```

### 3.3 云台状态帧

```text
方向：电控 -> 视觉/导航计算机
ID：ID_GIMBAL_STATE = 0x0E
结构：ReceiveGimbalStateData
总大小：49 bytes
```

串口节点解析后发布 `/serial/gimbal_state`，同时发布关节状态和 IMU 等 ROS 话题。

## 4. 配置参数

串口节点默认配置位于：

```text
src/standard_robot_pp_ros2/config/standard_robot_pp_ros2.yaml
src/pb2025_sentry_bringup/params/node_params.yaml
```

关键参数必须保持一致：

```yaml
device_name: /dev/ttyACM1
baud_rate: 115200
flow_control: none
parity: none
stop_bits: "1"
```

`device_name` 必须以实际设备为准。先执行：

```bash
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null
```

如果没有任何输出，说明 Linux 没有枚举到电控 USB，不能靠改 YAML 解决。若日志出现 `error -71`，应优先检查 USB 数据线、USB 口、电控板 USB 接口和 USB 供电。

## 5. 启动方式

### 5.1 推荐：启动整车入口

```bash
cd /home/ats/ATS
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 launch pb2025_sentry_bringup bringup.launch.py \
  world:=rmul \
  slam:=False \
  use_robot_state_pub:=False \
  use_composition:=True \
  launch_small_gicp_relocalization:=False
```

该入口会启动：

- `standard_robot_pp_ros2`；
- `sentry_chassis_vel_transform`；
- Nav2 和定位；
- `base_footprint -> base_link` 静态 TF；
- 行为树。

### 5.2 分开启动

如果只启动 Nav2，还必须另外启动串口和底盘转换：

```bash
ros2 launch standard_robot_pp_ros2 standard_robot_pp_ros2.launch.py
```

```bash
ros2 run sentry_chassis_vel_transform chassis_vel_transform_node \
  --ros-args --params-file \
  /home/ats/ATS/src/pb2025_sentry_bringup/params/node_params.yaml
```

同一时间只能启动一个 `standard_robot_pp_ros2`，避免两个进程抢占 USB 串口。

## 6. 联调检查

### 6.1 检查话题是否存在

```bash
ros2 topic list | grep -E 'cmd_vel|gimbal|serial'
```

### 6.2 检查底盘速度链

选定 Nav2 目标后执行：

```bash
ros2 topic info /cmd_vel -v
ros2 topic echo /cmd_vel --once
ros2 topic hz /cmd_vel
```

逐层检查：

```bash
ros2 topic hz /cmd_vel_controller
ros2 topic hz /cmd_vel_controller_governed
ros2 topic hz /cmd_vel_nav2_result
ros2 topic hz /cmd_vel_gimbal_yaw_odom
ros2 topic hz /cmd_vel
```

正常时 `/cmd_vel` 应有一个发布者 `chassis_vel_transform`，并有一个订阅者 `standard_robot_pp_ros2`。

### 6.3 检查视觉云台链

```bash
ros2 topic info /serial/gimbal_state -v
ros2 topic hz /serial/gimbal_state
ros2 topic echo /serial/gimbal_state --once

ros2 topic info /serial/gimbal_cmd -v
ros2 topic hz /serial/gimbal_cmd
ros2 topic echo /serial/gimbal_cmd --once
```

`/serial/gimbal_cmd` 应为 7 个元素，`/serial/gimbal_state` 应为 11 个元素。

## 7. 查看实际发送内容

串口节点支持 `log_cmd_vel` 参数。联调时将两个参数文件中的：

```yaml
log_cmd_vel: false
```

改为：

```yaml
log_cmd_vel: true
```

重新编译并启动后，串口节点终端会打印：

```text
[serial/input] cmd_vel vx=... vy=... wz=...
[serial/send] robot_cmd id=0x01 len=... vx=... vy=... wz=... stop=... mode=... bytes=...
```

含义：

- `[serial/input]`：串口节点收到的 ROS 底盘速度；
- `[serial/send] robot_cmd`：已组装并交给串口驱动的电控底盘帧；
- `bytes=`：完整十六进制帧，包含帧头、时间戳、数据和 CRC16。

视觉云台发送还会打印：

```text
[serial/cmd] received gimbal_cmd mode=... yaw=... pitch=...
[serial/send] gimbal_cmd id=0x02 mode=... yaw=... pitch=...
```

如果启动终端已经关闭，可搜索 ROS 日志：

```bash
rg -n "\[serial/input\]|\[serial/send\]|\[serial/cmd\]" /home/ats/.ros/log
```

判断方法：

| 现象 | 结论 |
|---|---|
| 没有 `[serial/input]` | `/cmd_vel` 没有到达串口节点 |
| 有 `[serial/input]`，没有 `[serial/send]` | 串口未打开或设备中途断开 |
| 两类日志都有，电控仍无数据 | 检查 USB、波特率、协议字段和电控接收程序 |
| `/serial/gimbal_cmd` 没有发布者 | 视觉桥接或视觉程序没有启动 |

## 8. 常见故障

### 8.1 `/cmd_vel` 没有发布者

通常是只启动了 Nav2，没有启动 `sentry_chassis_vel_transform`。启动完整入口，或单独启动该节点。

### 8.2 `base_link` 不存在

通常是没有启动完整 bringup。完整入口会发布 `base_footprint -> base_link` 静态 TF；也可以在临时联调时执行：

```bash
ros2 run tf2_ros static_transform_publisher \
  --frame-id base_footprint --child-frame-id base_link
```

### 8.3 `Open serial port failed`

依次检查：

```bash
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null
groups
```

如果设备存在但无权限，将当前用户加入 `dialout` 组后重新登录：

```bash
sudo usermod -aG dialout $USER
```

### 8.4 USB 日志出现 `error -71`

这是 USB 协议枚举失败。优先更换数据线、USB 口和 USB 2.0 集线器，并检查电控板 USB 接口和供电。设备未生成 `/dev/ttyACM*` 前，ROS 节点无法发送任何协议帧。

### 8.5 电控收到帧但底盘不动

检查：

1. 电控端是否按 `ID_ROBOT_CMD=0x01` 接收；
2. 电控端波特率是否与 `baud_rate` 一致；
3. `vx/vy/wz` 的单位、大小端和 float 布局是否一致；
4. `stop` 是否为真；
5. `mode` 是否为合法值；
6. 电控是否处于允许运动状态或急停状态。

## 9. 维护边界

| 修改内容 | 代码位置 |
|---|---|
| 修改 Nav2 速度生成链 | `src/pb2025_sentry_nav` |
| 修改云台视觉算法和 ROS 桥接 | `src/sp_vision25` |
| 修改 `/cmd_vel` 到协议字段映射 | `src/standard_robot_pp_ros2/src/standard_robot_pp_ros2.cpp` |
| 修改串口协议结构、ID、CRC | `src/standard_robot_pp_ros2/include/standard_robot_pp_ros2/packet_typedef*.hpp` |
| 修改串口设备、波特率 | 两个 YAML 参数文件 |
| 修改整车启动 | `src/pb2025_sentry_bringup/launch/bringup.launch.py` |

底盘和云台共用同一个串口节点时，任何协议结构修改都必须同步通知电控端，并使用十六进制帧日志做联调验证。
