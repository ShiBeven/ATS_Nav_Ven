# 云台各模式保护核查

核查日期：2026-10-24。范围：当前 D:\code-ai\双板通信的云台 源码，STM32F407、FreeRTOS、Pitch + 小Yaw + 大Yaw。只做静态检查，未修改控制代码、编译、烧录或实机验证；不将电脑源码当作板上固件证明。

## 1. 当前真正执行的模式

以 application/gimbal_task.c:190 的 switch 为准，名称以执行内容解释，避免被旧注释误导。

| 数值 | 枚举 | 实际作用 |
| --- | --- | --- |
| 0 | GIMBAL_ZERO_FORCE | 三轴零命令，无力 |
| 1 | GIMBAL_INIT | 三轴初始化归零 |
| 2 | GIMBAL_CALI | Pitch与小Yaw机械限位校准，大Yaw零命令 |
| 3 | GIMBAL_ABSOLUTE_ANGLE | 手动稳角，小Yaw/Pitch绝对角控制，大Yaw跟随小Yaw相对角回中 |
| 7 | GIMBAL_VISION | 实际是旧导航/自动俯仰扫描，小Yaw试图固定编码器1084 |
| 8 | AUTO_AIM | 自瞄，使用视觉任务算出的三轴命令 |

4（YAW2_LOCK）、5（FLOW_CHASSIS）、6（MOTIONLESS）、9（DOUBLE_YAW）只有枚举/部分声明，当前主循环没有对应执行分支，进入后走 default 调用无力函数，不能按名称认定具备独立控制和保护。

拨杆映射：RC_Right=0，RC_Left=1；两拨杆下位为无力，校准运行时优先执行校准。左下右中实际请求模式3，并不是注释写的独立初始化模式。从无力请求工作模式时通常先经过INIT。Vision_state非零请求自瞄，但随后两拨杆下位和左下右中分支仍可覆盖它；右下且左不下时，无视觉且AUTO开启才进入模式7。

## 2. 共用保护及实际范围

- 遥控：RC_data_is_error检查最后接收时间，超过100ms或尚未收到即错误；清空遥控量、将两拨杆置下，云台任务锁存dm_fault_latched并发三轴零命令。basic、aux、mouse和本地DBUS共用时间戳，因此不是每类遥控帧独立超时保护；原通道幅值/拨杆值检查被注释。
- DM：角速度反馈未收到、年龄超过20ms、Z值不在协议范围内，即视为离线。触发三轴无力，不是只停大Yaw。来源：components/devices/dm_imu.c:6。
- C板陀螺仪：BOARD_GYRO_TOE错误同样使三轴无力。detect_task配置离线阈值2 tick、上线稳定3 tick；tick为1ms，但检测任务每10ms轮询，不能说实际恰好2ms关断。
- 故障恢复：只有遥控、DM、C板陀螺仪都健康且两拨杆下位，才清除dm_fault_latched。单纯传感器恢复不会在原工作拨杆位置直接解除该锁存。
- 校准有效性：gimbal_cali_valid为0或校准状态3（失败）时阻止进入普通工作模式；有效校准过程有独立入口。
- 最终输出：公共门控在模式计算后再次发零、清普通云台PID；大Yaw另有最终命令限幅。这里是软件零命令，不是切断电源；仍需任务、定时中断和CAN发送正常运转。

主要位置：application/gimbal_task.c:164、222、283；application/remote_control.c:65、100；application/detect_task.c:216及application/detect_task.h:59。

## 3. 分模式保护

### 模式0：无力

Gimbal_Zero_Force清三轴命令及角度增量，关闭大Yaw测速测试。软件继续发送零命令。无力不提供位置保持或主动制动，Pitch可能因重力下垂。普通无力函数只明确清大Yaw普通速度PID；不能描述成所有普通与视觉PID都清零。

位置：application/gimbal_task.c:558。

### 模式1：INIT

- 进入编码器控制时用各轴实测相对角初始化目标，减少沿用旧目标导致的跳动。
- Pitch目标逐周期限制在校准得到的相对角上下限内；上下限无效时本周期三轴零命令并清普通云台PID。
- 大、小Yaw归零误差均需小于0.02rad（约1.15°），Pitch绝对角误差小于0.1rad（约5.73°），且IMU健康，连续满足100个控制周期才算完成并记录Yaw惯性零位。
- 最多6000个控制周期，按名义1ms周期约6秒；未完成时退出到无力，而非超时强行认作归零成功。
- Pitch速度环输出上限16000，小Yaw实际初始化使用的普通速度环上限25000；大Yaw还有公共最终10000命令限幅。

关键不足：INIT失败退出没有独立锁存。按GetgimbalMode分支推演，超时退无力的return发生在last_gimbal_behaviour更新之前，静态变量仍可能是INIT；若拨杆仍请求工作，下一周期可选中工作模式且不再触发“ZERO→INIT”条件。因此不能把当前INIT超时描述为持续禁止使能。此处为源码分支推演，未做运行验证。

位置：application/gimbal_task.c:290、327、398、591、638。

### 模式2：校准

- 两拨杆必须保持下位、遥控有效、DM/C板陀螺仪健康；启动时Pitch、小Yaw反馈都需在50ms内。
- 只驱动当前被校准轴；大Yaw和另一轴零命令。切步骤及结束等待校验时均清三轴命令。
- 当前轴反馈年龄超过50ms、未收到反馈、编码器超出0～8191均中止。
- 每一步最长12秒；设置命令必须大于0且不超过8000（软件命令单位，不可直接写成8000mA）。
- gimbal_cali_abort可主动中止；拨杆离开下位或公共故障立即失败。
- 至少经过300ms启动观察，RPM在±1内、编码器相对静止参考在±3计数内，连续约2秒判为端点；Pitch还要求陀螺仪速度小于0.1rad/s。
- 结束检查行程、方向、编码器合法性、有效范围；Pitch两端估算零位差不得超过0.05rad（约2.86°）。两端分别内缩0.1rad（约5.73°）生成工作边界。
- 失败清输出、清有效标志、保留首个错误及步骤并锁存状态3，不保存本次失败结果。重新做完整遥控校准手势才重新发起，后台回调不会自动重试。
- 错误码：1互锁/命令条件，2单步超时，3反馈/IMU，4行程或几何，5主动中止。旧超速中止已移除，6仅预留。

注意：静止判据不能可靠区分机械端点、摩擦卡住和其他阻挡；正常碰到机械限位的判定本身包含持续出力约2秒。12秒超时和限命令不等于碰撞/扭矩/温度保护。

位置：application/gimbal_task.c:757、780、918、965；application/gimbal_task.h:235附近；application/calibrate_task.c:281、397。

### 模式3：手动稳角/双Yaw跟随

- 入模式同步当前绝对角目标，减小切换跳变；遥控摇杆死区20。
- Pitch绝对角目标裁剪到校准上下限数值；这是目标裁剪，未根据实际编码器边界统一拦截继续向外的电流。绝对角和机械相对角的关系也依赖安装/姿态模型成立。
- Pitch、小Yaw角度环输出目标速度上限均10rad/s；Pitch速度PID命令上限16000。
- 小Yaw速度PID实际使用YAW_SPEED_PID_MAX_OUT=25000，不能只看到头文件YAW2_SPEED_PID_MAX_OUT=20000就认定是20000。
- 大Yaw跟随小Yaw相对角，死区0.02618rad（约1.5°），当前速度目标限幅2rad/s，最终命令限幅10000；参数合法范围检查与异常结果清零已经接入。
- 可选大Yaw测速测试最多输出2秒，随后维持零速度目标直到退出测试；速度、命令限幅仍适用。

不足：小Yaw已校准的min/max_relative_angle没有用于本模式的目标或最终输出限位；旧固定限角代码是注释。大Yaw跟随有助于小Yaw回中，但不能替代小Yaw硬性软限位。big_follow_speed_limit只限此跟随路径目标速度，不覆盖INIT/导航/自瞄，更不是测得超速后停机。

位置：application/gimbal_task.c:1028、1074、1100、1115、1443、1464、477。

### 模式7：旧导航/自动俯仰扫描

- 继承公共故障门控、普通PID限幅、大Yaw最终命令限幅。
- Pitch根据比赛时间在0～-0.55rad或0.3～-0.4rad附近切换扫描方向。这些是固定扫描目标，并非依据本次校准边界做安全裁剪。
- 未见Pitch目标按校准min/max_relative_angle限制，也未见小Yaw统一限位；进入该模式没有完整的当前目标同步。
- 小Yaw仍走原始编码器目标1084，不使用本次校准得到的新中点；yaw2_ecd、yaw2_motor的PID初始化代码目前被注释，所示源码中无其他有效初始化，不能把这段当成已正确启用的小Yaw锁定控制。
- Vision_state非零时函数直接return，不清历史三轴命令；正常选模通常会切自瞄，但不能将这个return当成停机保护。

位置：application/gimbal_task.c:1122、1193、1207、443。

### 模式8：视觉自瞄

- 三轴命令由Src/Vision_Task.c计算，Auto_Aim取结果；公共IMU/遥控故障门控仍覆盖三轴，大Yaw最终命令上限10000仍有效。
- 视觉角度环目标速度上限：Pitch 15、小Yaw 30、大Yaw10rad/s；三轴视觉速度PID各自输出上限25000，并有积分限幅。
- 但PID后继续叠加yaw_vel/pitch_vel，自瞄入口大Yaw又叠加转速补偿；Pitch、小Yaw没有叠加后的统一最终限幅，不能保证实际发送命令仍在±25000内。大Yaw虽有最终10000限幅，补偿发生在转换int16前且未做浮点统一边界检查，异常输入处理仍不完整。
- 未见Pitch/小Yaw按校准机械边界限制视觉目标，未见这两轴统一的NaN/Inf及物理合理范围检查。
- 通信正常配置USB_YAW_DEBUG=0时，统一协议校验帧长、CRC等，视觉mode范围检查；视觉100ms超时将mode置0，导航覆盖100ms超时撤销覆盖并按视觉新鲜度回退。丢视觉通常退出自瞄到由拨杆/AUTO决定的其他模式，不等于三轴自动无力。
- 当前实际宏USB_YAW_DEBUG=1，USB只发波形，不接收视觉/导航，正常USB接收及其超时逻辑均不执行。因此不能说当前默认构建能通过USB正常自瞄，也不能把另一编译分支的超时当作当前启用功能。

位置：Src/Vision_Task.c:138、219、230、237；application/gimbal_task.c:1222；application/usb_task.h:26；application/usb_task.c:124、133、149、183、242。

## 4. 尚未接入的通用保护

- 普通工作模式与INIT没有每个电机编码器反馈新鲜度的停机门控；带时间戳的gimbal_get_motor_snapshot主要用于校准。不能把IMU在线误当成三台电机都在线。
- 未见云台按电机温度、实际反馈电流、持续堵转或供电电压执行停机。CAN接收中保存温度不等于过温保护；PID输出限幅也不等于实际电流/温升检测。
- 未见统一覆盖全部模式的Pitch/小Yaw机械边界输出保护。
- gimbal_cmd_to_chassis_stop和gimbal_cmd_to_shoot_stop虽有定义，但源码未见有效调用，也未见gimbal_control_behaviour.gimbal_mode_data跟随实际模式更新。不能据此断言INIT/校准已经可靠联锁底盘与发射；其他独立任务/另一块板的保护需单独核查。
- CAN发送邮箱无空位时跳过发送，没有确认本次零命令已到电机，也没有在此层实现发送失败锁存。不能由软件变量变零直接证明总线和执行器均已停机。

## 5. 优先补齐顺序

1. 将INIT失败做成持续禁止工作的状态，并明确由两拨杆下位解除/重新归零，避免失败后下一周期绕过INIT。
2. 给全部主动模式接入Pitch/小Yaw统一机械限位，区分目标裁剪和越界时只允许朝安全方向输出。
3. 把三轴电机反馈新鲜度纳入公共使能条件。
4. 视觉前馈与补偿叠加后先检查浮点合法性、再统一限幅、最后转换int16；补齐目标角与速度合法性。
5. 按实机热负荷需求再明确堵转、温度等阈值，并验证跨板停底盘/停发射联锁。

这些是当前源码的保护完整性问题，不单凭此报告认定此前Pitch抖动或底盘卡顿的唯一原因。本轮不改变现有控制策略。
