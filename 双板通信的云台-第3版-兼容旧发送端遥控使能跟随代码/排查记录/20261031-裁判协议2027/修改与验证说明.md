## 已完成的修改

本工程已有裁判串口协议定义、解包、哨兵指令发送和辅助接口已按该版本更新。视觉/导航 USB 协议和板间 CAN 数据流是队内自定义接口，不与裁判链路的同名数字 ID 混用。未将自定义 0x5A USB 帧改为裁判 0xA5 帧。

### 接收与发送行为

- 对所有已实现固定命令校验帧头、CRC8、CRC16、提供的实际帧长和命令对应的数据段长。旧长度数据不会部分覆盖新版状态；未知命令不覆盖已有状态。
- `referee_data_solve` 现在返回接收是否成功，并显式接收实际帧长度。当前工程调用点已同步更新。
- 解包缓冲支持 300 字节数据段及 309 字节整帧；交互包仍单独限制为 118 字节数据段，不因扩大通用缓冲而放宽交互协议上限。
- 接收 FIFO 从 1024 扩为 2048 字节，解包任务由每 100ms 改为每 10ms 排空；哨兵指令保持 10Hz，低于协议对 0x0301 的 30Hz 总上限。
- USART6 保持电源管理 User 口所需的 115200、8N1、无硬件流控。取消初始化阶段把 USART6 临时挂到视觉缓冲的调用，改由裁判任务在专用 FIFO 初始化后启动 DMA。
- 只有本机 ID 为红/蓝哨兵 7/107 时发送 0x0120；上电 ID 未知或其他兵种不发送非法的哨兵命令。接收者仍为 0x8080，长度 19 字节。
- 保留原有满足免费复活条件时确认复活的行为；姿态允许 1-6，无效姿态默认 3。`sentry_activate_rune` 默认 0，置 1 时使用新版 bit24，不会默认主动激活能量机关。付费复活和兑换请求继续保持零。
- 导航包 `speed_vector.mode` 的枚举改为 Attack=1、Defend=2、Move=3、强化姿态=4/5/6，以匹配它生成的官方哨兵姿态指令。ARMCC 编译断言确认自定义导航结构仍为 52 字节，ATS 线上兼容帧仍为 54 字节。
- 板间 `game_state_t.current_Hp` 改为 uint16_t，避免已有双字节 CAN 解码被本地单字节字段截断；CAN 线上字节格式保持原样。

## 范围与实机限制

本次完成的是当前云台工程已存在接口与该 PDF 的冲突修正。没有烧录、连接裁判系统或实机验证，也没有修改用户其他同名项目、底盘板独立工程或 ATS 上位机源码。底盘若也直接解析裁判串口，需要在其独立工程同步升级。

0x0310/0x0311 属于 921600 图传链路，本次已修正已有类型和通用解码容量，但没有把当前 115200 裁判 User 口改接图传模块。雷达无线链路 0x0A01-0x0A06 和自定义终端 MQTT/Protobuf 在本工程中没有现有实现，本次不新增相关设备或应用；这不表示已实现整份 PDF 的所有功能。

自定义 USB/板间 CAN 的坐标系、视觉仲裁、PID、超时保护及控制模式选择不由本 PDF 定义，本次保留其现有行为；强化姿态的官方指令可发送，不额外改写现有视觉接管条件。
