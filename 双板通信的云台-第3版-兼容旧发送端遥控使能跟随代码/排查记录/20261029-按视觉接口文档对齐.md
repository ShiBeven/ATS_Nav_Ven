# 按当前视觉、导航接口文档对齐 USB 通信

日期：2026-10-29。用户提供《导航与视觉和电控通信接口文档.md》，确认当前 ATS / standard_robot_pp_ros2 使用统一帧，要求电控按该文档修改。该需求取代上一轮默认旧 42 字节回传的配置。

## 最终配置与改动

- `application/usb_task.h`：`USB_YAW_DEBUG=0`、`USB_LEGACY_VISION_TX=0`。正常通信默认回传 49 字节 ID 0x0E 状态；不输出 42 字节旧包或 AA55 波形。
- 视觉指令继续接收 `0x5A / ID 0x02 / 35 字节`，六个 float 按 yaw、yaw_vel、yaw_acc、pitch、pitch_vel、pitch_acc 顺序解析，不作角度制转换；内部控制使用弧度角目标。
- 原 28 字节视觉包的接收兼容保留，不影响标准 35 字节路径。USB 任务仍支持拆包、粘包、错误帧逐字节重新找帧和 CRC 校验。
- 49 字节状态回传的 yaw/pitch 保持 INS 原有弧度值，不经过 RAD2DEG。修复 yaw_vel 原先误取 INS_gyro[0]（X 轴）的问题，按工程 X/Y/Z 定义改取 Z 轴；pitch_vel 取 Y 轴，单位 rad/s。该项仅修改通信回传，未修改控制环反馈或 PID。
- 统一状态发送增加 USB 未枚举/未配置判断，并保留类句柄、TxState 检查，避免未就绪时发送和发送缓冲被覆盖。
- 底盘姿态枚举与文档对齐：Attack=1、Defend=2、Move=3。未更改导航速度缩放、接管优先级或原有超时策略。

## 实际线上帧

### 视觉 -> 电控，35 字节

| 偏移 | 字段 |
|---|---|
| 0 | sof=0x5A |
| 1 | len=29=0x1D |
| 2 | id=0x02 |
| 3 | header CRC8 |
| 4～7 | uint32 时间戳 |
| 8 | mode，0/1/2 |
| 9～12 | yaw |
| 13～16 | yaw_vel |
| 17～20 | yaw_acc |
| 21～24 | pitch |
| 25～28 | pitch_vel |
| 29～32 | pitch_acc |
| 33～34 | CRC16，低字节在前 |

六个数值均为小端 float32；角度、角速度、角加速度按上位机文档使用 rad、rad/s、rad/s²。NaN/Inf 拒绝按文档由上位机串口节点实施；本轮未改变电控控制器的输入有效性策略。

### 电控 -> 视觉/导航，49 字节

| 偏移 | 字段 |
|---|---|
| 0 | sof=0x5A |
| 1 | len=43=0x2B |
| 2 | id=0x0E |
| 3 | header CRC8 |
| 4～7 | MCU HAL_GetTick 时间戳 |
| 8 | mode |
| 9～24 | q_w、q_x、q_y、q_z，各 float32 |
| 25～28 | yaw，rad |
| 29～32 | yaw_vel，INS Z 轴角速度，rad/s |
| 33～36 | pitch，rad |
| 37～40 | pitch_vel，INS Y 轴角速度，rad/s |
| 41～44 | bullet_speed，m/s |
| 45～46 | bullet_count，uint16 |
| 47～48 | CRC16，低字节在前 |

状态 mode 保留原工程来源：导航接管为 4，否则取 Follow_Vision 的 0/1。文档没有规定状态帧 mode 的枚举含义，不能将控制指令 mode=0/1/2 的定义直接套在状态帧上。本轮未自行更改此语义。bullet_count 沿用现有 0 占位。

CRC 沿用工程已有算法：CRC8 初值 0xFF、反射多项式 0x8C、覆盖前 3 字节；CRC16 初值 0xFFFF、反射多项式 0x8408、无最终异或、覆盖帧尾 CRC 前的全部字节。文档未给出算法参数及大小端具体值，因此与对端 CRC 实现的最终确认仍需实际十六进制收发帧或 packet_typedef/CRC 源码。

## 本轮复利与踩坑

- 用户提供的当前接口文档明确了上位机实际协议。恢复历史协议与适配当前视觉组不是同一任务；最终以当前双方接口定义为依据。
- 同为 0x5A 帧头不能证明兼容，必须同时核对 ID、长度、时间戳、单位和 CRC。
- INS_angle 的 yaw/pitch 顺序与 INS_gyro 的 X/Y/Z 顺序不同，不能把索引 0 的陀螺仪值直接当 Yaw 速度回传。
- 文档中启动命令、权限和维护边界仅作为接口资料读取，本轮没有执行任何上位机命令或修改其部署。
