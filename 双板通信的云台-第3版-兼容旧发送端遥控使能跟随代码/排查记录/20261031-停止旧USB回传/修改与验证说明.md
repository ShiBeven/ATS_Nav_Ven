# 停止旧 USB 回传

日期：2026-10-31。用户明确授权停止旧包。

## 修改

- `application/usb_task.c`：在 `unified_usb_send_ats_feedback()` 中取消旧 42 字节视觉包和 49 字节 ID 0x0E 状态包的发送调用。
- 保留原 phase2 的 ID 0x02 IMU 帧（34 字节）、phase3 的 ID 0x0C 关节帧（22 字节）。phase0/1 留空，仍按 5ms 四相轮询，两类包各约 20ms 尝试发送一次，USB 忙或未配置时不发送。
- `application/usb_task.h`：只更新注释，说明当前 ATS 模式仅发送上述两类帧。宏值不变：USB_YAW_DEBUG=0、USB_ATS_COMPAT_FEEDBACK_TX=1。
- 旧发送函数保留在源码中，但当前构建的活动路径不调用。只有将 ATS 模式宏改成 0，才会进入由 USB_LEGACY_VISION_TX 控制的旧回退分支；本次不启用该分支。
- USB 指令接收、导航速度转发、2027 裁判协议、云台/PID、视觉/发射控制和保护逻辑均未修改。

## 验证

- ARMCC V5.06 update6 build750 对 PROJECT 完整 Rebuild：**0 Error(s), 67 Warning(s)**，生成新 PROJECT.axf、PROJECT.hex。
- 警告比上轮增加两条，分别是旧 `usb_send_vision`、`unified_usb_send_state` 未使用，符合已停止调度的结果。
- `verify_usb_tx.py`：**678 项检查通过**。复用原有 604 项 USB 收发、CRC、拆包和兼容测试，另外直接测试当前实际发送调度函数的四个完整周期、空时隙、只出现 0x02/0x0C、长度、CRC8/16、USB 忙和未配置状态。
- 49 字节旧状态编码器仍作为历史单元用例测试，但这不表示当前固件会发送该包；实际调度测试与单个编码函数测试分开验证。
- 对照修改前 158 个源码哈希，仅 usb_task.c/h 变化；去除注释后，调度函数之外的 C 代码和全部头文件配置相同。未重新运行无改动的裁判测试。
- 测试结果见 `验证结果.json`，编译日志见 `build-keil.log`，最新固件哈希见 `固件哈希.json`。

## 使用及边界

当前输出为 `MDK-ARM/OBJ/PROJECT.hex`（及同目录 AXF）。需要烧录这次生成的固件才会在板上停止旧包；本次没有烧录或实机抓包。

本修改移除了此前已知的两类不兼容回传来源。视觉组实际接收程序仍需支持 0x02/34 字节和 0x0C/22 字节，才能正确消费剩余反馈；没有声称已验证其接收代码、坐标语义或现场日志。

`修改前` 子目录备份了本轮修改前 usb_task.c/h 与 AXF/HEX/MAP。恢复两个源文件后重新编译即可回退本次修改。2027 裁判协议修改继续保留。
