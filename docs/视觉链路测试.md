# 视觉链路测试

导航链路已经跑通后，按下面步骤单独验证视觉链路。

视觉主链路为：

```text
相机 -> YOLO -> Tracker -> Planner -> /serial/gimbal_cmd
```

## 1. 环境

```bash
source /opt/ros/humble/setup.bash
source ~/ATS/install/setup.bash
cd ~/ATS
```

## 2. 启动导航和串口

按照 [复用原地图选点导航.md](./复用原地图选点导航.md) 启动串口和导航。

已经启动导航后，不要再次启动 `ats_full.launch.py`，避免重复占用串口。

## 3. 启动视觉

另开终端执行：

```bash
source /opt/ros/humble/setup.bash
source ~/ATS/install/setup.bash

ros2 run sp_vision25 auto_aim_debug_mpc \
  ~/ATS/install/sp_vision25/share/sp_vision25/configs/standard3.yaml
```

如果安装目录中的配置不是最新版本，可以临时使用源码配置：

```bash
ros2 run sp_vision25 auto_aim_debug_mpc \
  ~/ATS/src/sp_vision25/configs/standard3.yaml
```

浏览器打开 Web 调试页面：

```text
http://127.0.0.1:8090/
```

## 4. 检查相机和云台数据

另开终端执行：

```bash
source /opt/ros/humble/setup.bash
source ~/ATS/install/setup.bash

ros2 topic hz /serial/gimbal_state
ros2 topic echo /serial/gimbal_state --once
```

正常要求：

1. `/serial/gimbal_state` 持续发布。
2. 消息数组长度为 `11`。
3. 四元数、云台 yaw/pitch、弹速等字段不是全零。

再检查视觉输出：

```bash
ros2 topic hz /serial/gimbal_cmd
ros2 topic echo /serial/gimbal_cmd
```

消息数组长度应为 `7`。

如果云台状态 `mode=4` 或 `mode=5`，视觉桥接会主动丢弃 `/serial/gimbal_cmd`，这是导航优先仲裁，不代表视觉识别失败。

## 5. 静态目标识别测试

当前配置使用蓝色目标：

```yaml
enemy_color: "blue"
min_confidence: 0.8
```

准备一个蓝色装甲板，放在相机前约 3 到 5 米处，先保持目标静止。

在 Web 调试页面观察：

1. 是否能框住完整装甲板。
2. `has_target` 是否变为 `true`。
3. `target_name` 和 `armor_type` 是否正确。
4. `tracker.match_valid` 是否稳定为 `true`。
5. `tracker.reprojection_px` 是否较小且没有持续跳变。
6. 目标不在画面中时，`has_target` 是否恢复为 `false`。

## 6. 角度测试

固定目标位置，记录 Web 页面中的 `target_yaw`、`target_pitch`、`plan_yaw`、`plan_pitch`。

将目标缓慢向画面右侧移动，再移回画面中央。

正常要求：

1. `target_yaw` 连续变化，没有突然跳变。
2. yaw 变化方向与云台实际转动方向一致。
3. 目标回到画面中央后，yaw/pitch 接近原值。
4. `/serial/gimbal_cmd` 中的 yaw/pitch 指令随目标变化。

如果左右方向相反，优先检查 `R_camera2gimbal`，不要先修改 PID。

## 7. 距离测试

用卷尺测量相机到装甲板的实际距离，同时观察 Web 页面中的 `target_x_m`、`target_y_m`、`target_z_m`。

检查目标坐标计算出的距离是否接近实测距离。

误差明显时，检查 `configs/standard3.yaml` 中的 `camera_matrix`、`distort_coeffs`、`R_camera2gimbal`、`t_camera2gimbal`。

## 8. 跟踪测试

缓慢左右移动目标，观察：

1. 目标 ID 是否保持。
2. `match_valid` 是否连续。
3. `reprojection_px` 是否稳定。
4. `target_yaw` 是否平滑。
5. 短暂遮挡后，跟踪是否能恢复。
6. 目标消失后，是否在合理时间内清除跟踪状态。

## 9. 记录调试视频

需要复盘时，启动原始画面和调试画面录制：

```bash
ros2 run sp_vision25 auto_aim_debug_mpc \
  ~/ATS/install/sp_vision25/share/sp_vision25/configs/standard3.yaml \
  --record-raw-video true \
  --record-debug-video true
```

默认保存到：

```text
~/ATS/records/
```

## 10. 当前接口边界

当前 `auto_aim_debug_mpc` 的生产闭环是：

```text
相机 -> YOLO -> Tracker -> Planner -> /serial/gimbal_cmd
```

代码中虽然存在 `vision/target` 发布器，但当前主程序没有实际调用它。因此：

```bash
ros2 topic echo /vision/target
```

没有数据时，只能说明视觉目标消息尚未接入当前主程序，不能据此判断 YOLO 或自瞄识别失败。

## 11. 验收顺序

1. 相机有图。
2. YOLO 能稳定识别蓝色装甲板。
3. Tracker 不跳目标。
4. yaw/pitch 方向和数值正确。
5. `/serial/gimbal_cmd` 输出正确。
6. 最后再联调行为树和视觉目标导航。
