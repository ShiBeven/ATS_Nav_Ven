# 复用原地图选点导航

不建图、不启动 small_gicp 重定位，直接使用 `rmul` 原地图。当前导航控制速度链为：

```text
Nav2 MPPI controller (`cmd_vel_controller`)
 -> trajectory_speed_governor (`cmd_vel_controller_governed`)
 -> velocity_smoother
 -> `cmd_vel_nav2_result`
 -> fake_vel_transform
 -> cmd_vel_gimbal_yaw_odom
 -> sentry_chassis_vel_transform
 -> /cmd_vel
```

此流程用于已对齐地图原点的手动选点测试。关闭重定位后，`map -> odom` 使用零位静态 TF；车辆启动位置和朝向必须与地图原点一致。起点未知或每次上电位置不同，使用[上场使用流程](../上场使用流程.md)中的 small_gicp 重定位入口。

## 1. 环境

```bash
source /opt/ros/humble/setup.bash
source ~/ATS/install/setup.bash
cd ~/ATS
```

## 2. 启动串口和机器人 TF

```bash
ros2 launch standard_robot_pp_ros2 standard_robot_pp_ros2.launch.py
```

该启动文件还会启动机器人描述和关节状态发布。确认串口参数与电控固件一致；当前项目配置为 `/dev/ttyACM1`、`115200`。
串口节点启动时会先初始化串口设备参数，再打开设备；同一时间只能启动一份
`standard_robot_pp_ros2`，否则会重复占用串口。

本导航流程不启动 `sp_vision25`，因此不会产生视觉 `cmd_gimbal` 控制，也不会触发
视觉控制源仲裁。若同时进行视觉联调，应遵循[视觉链路测试](./视觉链路测试.md)中的
启动约束，不要再启动另一份 `standard_robot_pp_ros2`。

## 3. 启动底盘速度转换

另开终端执行：

```bash
source /opt/ros/humble/setup.bash
source ~/ATS/install/setup.bash

ros2 run sentry_chassis_vel_transform chassis_vel_transform_node \
  --ros-args --params-file ~/ATS/src/pb2025_sentry_bringup/params/node_params.yaml
```

该节点把导航的 `cmd_vel_gimbal_yaw_odom` 转换为串口节点订阅的绝对话题 `/cmd_vel`。

## 4. 启动导航

```bash
ros2 launch pb2025_nav_bringup rm_navigation_reality_launch.py \
  world:=rmul slam:=False \
  launch_small_gicp_relocalization:=False \
  launch_chassis_vel_transform:=False \
  use_robot_state_pub:=True \
  use_rviz:=True
```

第 3 步已手动启动 `sentry_chassis_vel_transform`，所以这里关闭导航 launch 自带的同名节点，避免重复发布 `/cmd_vel`。第 2 步已启动串口和机器人状态发布，所以设置 `use_robot_state_pub:=True`，避免导航 launch 再发布重复的底盘 TF。

不要同时启动 `ats_full.launch.py` 和本节的 `standard_robot_pp_ros2.launch.py`；前者若已包含串口入口，
会与本节启动的串口节点竞争同一个设备。导航测试只保留一份串口节点和一份底盘速度转换节点。

## 5. RViz 选点

1. 手放急停。
2. 点击 `Nav2 Goal`。
3. 在原地图上点击目标点并拖出朝向。
4. 松开鼠标发送目标。

不要使用 `2D Pose Estimate`。

## 6. 检查速度链

```bash
ros2 topic hz /cmd_vel_gimbal_yaw_odom
ros2 topic hz /cmd_vel
ros2 topic echo /serial/gimbal_joint_state --once
```

选点后，`/cmd_vel_gimbal_yaw_odom` 和 `/cmd_vel` 应在导航运动期间有数据。若前者有数据而后者没有，优先检查 `sentry_chassis_vel_transform` 是否启动，以及 `serial/gimbal_joint_state` 是否存在。
